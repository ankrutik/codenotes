- #apidesign
	- In #interviews this phase should take no more than 5 minutes
	- #systemdesign/choice API methods
		- [[REST]] over HTTP is the default choice
		- [[GraphQL]] request exactly what you need, avoid over/under fetching
		- [[RPC]] used for internal
	- [[REST]]
		- plural nouns, no verbs!
		- verb in the HTTP method #apidesign/choice
			- GET retrieve
			- POST create
			- DELETE remove
			- PUT idempotent update/replace
			- PATCH partial update
		- Specificity towards the right
			- ```
			  GET /events
			  GET /event/{id}
			  GET/event/{id}/tickets
			  ```
		- Inputs
			- Path param `GET /events/{id}`
				- Compulsory When you want to identify a resource
			- Query params `GET /events?city=Mumbai&date=2025-01-10`
				- Optional filters or further refinement
			- Request body
				- Mostly with POST
				- ```
				  POST /events
				  {
				  	title,
				      description
				  }
				  ```
		- Responses
			- status code and response body
			- See [[HTTP Response Codes]]
	- [[GraphQL]]
		- Open sourced in 2015
		- Query and request exactly what you want. No less, no more.
		- ```
		  POST /events
		  Body ->
		  query{
		  	event(id: "1234"){
		      	name
		          date
		          venue {
		          	name
		              address
		          }
		      }
		  }
		  ```
		- #lookup Scheme Resolver for authorization
		- #lookup Data Loader for N+1 queries
	- [[RPC]]
		- very efficient intra-microservice communication
		- Calling method directly over a service instead of HTTP REST
		- Far less size of packets since it doesn't need to be human readable
		- Why not for Web applications?
			- Clients are diverse (browsers, mobile, etc)
			- Need for debugging at client side
		- [[gRPC]]
			- allows generating client and server code
			- for multiple platform endpoint (Java, python, etc)
			- using a single spec in a language called protocol buffer
				- `.proto` files
	- Other considerations
		- Pagination
			- #systemdesign/choice Page vs. Cursor
			- Limit
		- Security
			- Which endpoints are authenticated?
			- The request params or body will not have identification. It will be assumed from the authentication.
			- Examples #systemdesign/choice
				- JWT
				- Session token
			- Shorthand for auth
			  ```
			  @auth: admin
			  POST /delete/{id}
			  ```
